# Журнал: импорт банковской выписки (PDF) → вкладка "Операции"

Цель: пользователь загружает PDF-выписку по карте, получает превью распознанных
операций, правит их вручную и сам выбирает, что импортировать в журнал операций.
Никакой автоматики по дублям и категориям — это явная договорённость (см. ниже).

## Шаг 1 — фреймворк парсеров выписок + парсер Альфа-Банка (коммит: 7effc0e)
**Дата:** 2026-06-28
**Что сделано:**
- Пакет `backend/app/services/statement_parsers/` — реестр `PARSERS`/`BANKS`,
  расширяемый под другие банки без переделки API (новый банк = новый модуль +
  строка в реестре).
- `alfa_by.py` — парсер выписки Альфа-Банка (РБ). Использует
  `pdfplumber.extract_tables()` (не `extract_text()` — текстовый поток
  перемешивает порядок слов в ячейках, переносящихся на 2 строки, табличное
  извлечение этой проблемы не имеет).
- Пропускает строки со статусом ≠ "Завершено успешно".
- `is_income` определяется **только** по явному знаку `+`/`-` перед суммой; если
  знака нет — расход по умолчанию, пользователь правит вручную в превью. Никаких
  эвристик по ключевым словам типа операции (осознанное решение — не усложнять).
- `category` = колонка "Детализация" (прямое копирование, без догадок).
- `backend/pyproject.toml` — добавлена зависимость `pdfplumber`.
- `backend/tests/fixtures/sample_statement_alfa_by.pdf` — синтетическая выписка
  (вымышленные ФИО/счёт/транзакции, сгенерирована одноразовым скриптом через
  `reportlab`, который не закоммичен — только результат).
- `backend/tests/test_pdf_statement_parser.py` — юнит-тесты парсера.

**Почему так:** табличный парсинг pdfplumber устойчивее построчного regex-разбора
текстового потока — проверено на реальной выписке пользователя (не коммитилась в
репозиторий, содержит личные данные) и на синтетической фикстуре.

**Как проверить:** `cd backend && pytest tests/test_pdf_statement_parser.py -v`.

## Шаг 2 — эндпоинты импорта (коммит: 35a953f)
**Дата:** 2026-06-28
**Что сделано:**
- `GET /api/meta/import-banks` — список банков с доступным парсером (для
  выпадающего меню на фронте).
- `POST /api/operations/import/parse` — multipart (`file` + `bank`), валидация
  `content-type`/размера (≤10 МБ)/известности банка, возвращает
  `list[OperationCreate]` **без сохранения** (превью).
- `POST /api/operations/import/confirm` — принимает отобранные пользователем
  строки превью, создаёт операции через существующий `operation_repo.create`.
- Модель/схема `Operation` не менялись — превью использует тот же
  `OperationCreate`, что и обычная ручная форма. Никакого отслеживания дублей по
  номеру транзакции — пользователь сам решает, какие строки оставить (чекбоксы на
  фронте).
- `backend/pyproject.toml` — добавлена зависимость `python-multipart` (нужна
  FastAPI для `UploadFile`/`Form`).
- `backend/tests/test_operations_import.py` — интеграционные тесты (неизвестный
  банк, не-PDF файл, отсутствие авторизации, успешный сценарий parse→confirm).

**Почему так:** превью отделено от сохранения, чтобы пользователь мог поправить
категорию/тип и исключить ненужные строки до того, как они попадут в журнал
операций.

**Как проверить:** `cd backend && pytest tests/test_operations_import.py -v`.

## Шаг 3 — фронтенд: импорт PDF на вкладке "Операции" (коммит: <hash>)
**Дата:** 2026-06-28
**Что сделано:**
- `frontend/src/api/client.ts` — `api.postForm` для multipart-загрузки (без
  ручного `Content-Type`, браузер сам выставляет boundary).
- `frontend/src/api/resources.ts` — `metaApi.importBanks`,
  `operationsApi.importParse`, `operationsApi.importConfirm`.
- `frontend/src/components/ImportPreviewModal.tsx` — превью распознанных
  операций: чекбоксы (по умолчанию все выбраны — без логики дублей), редактируемые
  дата/тип/категория/описание/сумма, кнопка "Импортировать выбранные (N)".
- `frontend/src/pages/OperationsPage.tsx` — блок импорта (выбор банка + файл)
  рядом с формой ручного добавления операции; открывает превью-модалку по
  результату `importParse`.
- `frontend/src/styles.css` — `.modal-card-wide`, `.import-bar`.

**Почему так:** превью переиспользует существующие компоненты формы
(`NumberField`, datalist категорий) и паттерн модалки (`modal-overlay`/`modal-card`,
как в `AccountModal`/`AuthModal`) — никакой новой инфраструктуры.

**Как проверить:** `cd frontend && npm run build`; вручную — вкладка "Операции",
выбрать банк, загрузить PDF, отредактировать/отметить строки в превью, подтвердить
импорт, убедиться что в таблице операций появились только выбранные записи.
