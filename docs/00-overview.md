# OhMyBudget — выжимка по проекту

> Этот документ — краткая сводка договорённостей из обсуждения. На него опираемся
> при реализации. Подробности по слоям — в соседних файлах `docs/`.

## Что строим

Личный бюджет-трекер. Исходная спецификация (`plan.md`) описывает его как «семь
листов» Google-таблицы:

1. **Планы по месяцам** — ожидаемые доходы/расходы на каждый месяц.
2. **Операции** — журнал реальных доходов/расходов.
3. **Сводка** — 12 расчётных показателей за выбранный месяц.
4. **Инвестиции** — вклады/облигации, среднемесячный доход.
5. **Активы** — где и сколько денег хранится на даты, ИТОГО.
6. **История** — сводка по всем месяцам, план vs факт.
7. **Графики** — визуализация по данным сводки/истории.

Превращаем «листы» в **веб-приложение с чёткой изоляцией слоёв**: frontend /
backend / данные.

## Технологический стек (согласовано)

| Слой      | Технологии                                            |
|-----------|-------------------------------------------------------|
| Данные    | SQLite (local/pytest) / PostgreSQL (Docker) + SQLAlchemy 2.0 + Alembic |
| Backend   | Python (3.11+, локально 3.14) + FastAPI + Pydantic v2 |
| Frontend  | React + TypeScript + Vite + TanStack Query + Recharts |
| Запуск    | Docker Compose **и** локальный (uvicorn + npm)        |
| Node      | v26 / npm 11 (установлен через Homebrew)              |

## Ключевые архитектурные принципы

1. **Листы ≠ ячейки.** Хранятся только данные (4 сущности + справочники).
   Производные листы (Сводка, История, Графики) **вычисляются на бэке по запросу**,
   в БД не лежат.
2. **Три изолированных слоя:**
   - Данные: `models/` + `repositories/` — единственные, кто знает про SQL.
   - Backend-логика: `services/` (расчёты) + `api/routes/` (HTTP). Наружу — Pydantic.
   - Frontend: общается с бэком только через `src/api/` (REST/JSON), про БД не знает.
3. **Multi-tenant** — JWT Bearer, данные изолированы по `user_id` (см. `docs/07-auth.md`).

## Решения по итогам ревью (отличаются от наивной трактовки спеки)

Эти решения приняты осознанно — при реализации не «возвращаться» к буквальной спеке:

- **Доход/Расход хранится как `is_income: bool`**, не строкой. Текст
  «Доход»/«Расход» резолвится на фронте.
- **Месяцы — таблица-справочник** `months` (с `order_index`), не Python-константа.
- **Период плана = `year:int` + `month_id` (FK → months).** У операций — обычная
  `date`; при расчётах бэк раскладывает дату в (год, индекс месяца).
- **У планов нет поля `position`.** Порядок строк — целиком забота клиента.
- **Тип ценной бумаги — справочник** `security_types` (FK), не enum.
- **`payouts_per_year` — `float`, без ограничения** набором {12,4,2,1}.
- **Инвестиции — минимальный скелет** (CRUD + базовая формула). Глубокая логика
  отложена.
- **Сортировка операций и активов — на клиенте, экраном.** Бэк отдаёт без
  навязанного порядка; новые записи на фронте встают в нужную позицию.
