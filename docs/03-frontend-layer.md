# Frontend

> React + TypeScript + Vite. Общается с бэком **только** через `src/api/` (REST/JSON),
> про БД ничего не знает. 7 экранов = 7 листов спеки.

## Слой доступа к API (`src/api/`)

- `client.ts` — fetch-обёртка + baseURL (в dev Vite проксирует `/api` → :8000),
  JWT Bearer из `localStorage`, обработка 401.
- `auth.ts` — register, login, me.
- по файлу на ресурс: `lookups.ts`, `plans.ts`, `operations.ts`, `investments.ts`,
  `assets.ts`, `summary.ts`, `history.ts`.

## Авторизация (`src/context/AuthContext.tsx`)

- `AuthProvider` — user state, login/register/logout, `queryClient.clear()` на выход.
- `AuthModal` — вход/регистрация по кнопке в шапке или при попытке сохранить запись гостем.
- Гостевой режим: все экраны доступны; мутации через `runWithAuth` (см. `docs/08-guest-mode.md`).
- Подробности — [`docs/07-auth.md`](07-auth.md).

## Типы (`src/types/`)

TS-типы — зеркало Pydantic-схем бэка. Доход/Расход приходит как `is_income: boolean`.

## Утилиты (`src/lib/`)

- `formatType(is_income)` → «Доход» / «Расход» (резолв текста на фронте).
- сортировка списков (операции/активы по дате) и вставка новой записи в правильную
  позицию согласно активной сортировке (сортировка — на клиенте, не на бэке).

## Переиспользуемые компоненты (`src/components/`)

- `DataTable` — универсальная таблица.
- `EntryForm` — форма добавления (конфигурация полей на каждый лист).
- `SelectField` — выпадающий список из справочника (месяцы / типы ЦБ / типы активов)
  — защита от опечаток.

## Экраны (`src/pages/`)

| Экран             | Содержимое                                                                 |
|-------------------|----------------------------------------------------------------------------|
| `PlansPage`       | Таблица блоками по месяцам (группировка на клиенте). Форма: год, месяц-select, категория, тип-toggle (`is_income`), сумма. Кнопка «План на след. месяц» (clone-next). |
| `OperationsPage`  | Форма + таблица. Сортировка/вставка экраном (по умолчанию новые сверху, но управляет клиент). Категория — datalist из `/api/meta/categories`. |
| `SummaryPage`     | Селектор месяца (`/api/summary/months`), поле ввода остатка на начало, 12 показателей. Пересчёт при смене месяца. |
| `InvestmentsPage` | Таблица + столбец «Среднемесячный доход» (с бэка) + плашка «Общий». Минимальный вид. |
| `AssetsPage`      | Форма + таблица (сортировка по дате на клиенте) + плашка «ИТОГО».          |
| `HistoryPage`     | Таблица по всем месяцам (план/факт, отклонения).                          |
| `ChartsPage`      | Recharts по `/api/history`: план vs факт доходов/расходов, динамика остатка, отклонения. |

## Состояние и данные

- **TanStack Query** — загрузка данных и инвалидация кэша после мутаций.
- Справочники (`months`, `security_types`, `asset_types`) грузятся один раз и
  кэшируются.

## Навигация

- `App.tsx` — табы/меню на 7 страниц.
- `main.tsx` — точка входа, провайдер TanStack Query.

## Файлы конфигурации

- `vite.config.ts` — dev-proxy `/api` → backend :8000.
- `package.json` — React, TS, Vite, @tanstack/react-query, recharts.
